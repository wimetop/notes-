# Нотатки+ — UI refresh

## Мета

Оновити інтерфейс персонального нотатника, не змінюючи його API, авторизацію чи
нотаткові сценарії. Головні результати: зрозумілий перехід між входом і
реєстрацією та видимий контекст залогіненого користувача на робочих екранах.

## Напрям

**Нічний записник.** Це стриманий, теплий робочий простір для особистих думок:
глибокий графітовий canvas, світлі ``паперові`` поверхні, лавандово-індиговий
акцент і виразна, але не декоративна типографіка. Інтерфейс не імітує фізичний
зошит і не перетворюється на SaaS-дашборд: його впізнаваний жест — маленький
індекс-ярлик на картках і у шапці, що організовує записи як особистий архів.

Display-заголовки використовують `Georgia` з якісними системними serif

Радіуси м'які, але не pill: 12px для контролів, 18px для поверхонь.

## Екрани

### Вхід і реєстрація

Обидва екрани використовують одну auth-композицію: на десктопі — вузька форма
на світлій картці та темна інформаційна панель, на мобільному — одна картка без
декоративної панелі. Форма входу має явне посилання «Вперше тут? Створити
акаунт» на `/register`; форма реєстрації симетрично пропонує «Вже є акаунт?
Увійти» на `/login`. Поля, помилки та busy-стани лишаються семантичними й
доступними; password-manager і вставлення пароля не блокуються.

### Робоча зона `/notes`

Шапка містить бренд, навігацію до нотаток/кошика й профіль користувача справа.
Профіль показує круглий аватар з ініціалом, ім'я, а під ним email; на вузькому
екрані лишається аватар та коротке ім'я. Дані беруться лише з серверної Better
Auth сесії, а не з клієнтського сховища.

Сторінка має короткий заголовок, пошук із доступним очищенням, панель створення
та список нотаток. Поверхні отримують єдину карткову мову; create-форма не
конкурує зі списком за увагу. Кошик і редактор отримують ті самі шапку,
контейнери, стани керування та адаптивний ритм.

## Компонентні межі

- `Header` приймає server-derived користувача через dashboard layout і не
  запитує/зберігає сесію самостійно.
- `AuthForm` отримує декоративний auth-shell і компактний навігаційний footer;
  автентифікаційна логіка Better Auth не змінюється.
- Глобальні CSS-змінні в `globals.css` — єдине runtime-джерело токенів.
- Наявні форми й mutation hooks залишаються canonical owner валідації,
  pending/error станів і CRUD-поведінки згідно з `UX-CONTRACT.md`.

## Доступність і перевірка

- WCAG 2.2 AA: контраст, видимий focus, семантичні `button`/`a`, підписані
  inputs та живі повідомлення про помилки.
- Адаптивність: від однієї колонки на телефоні до двоколонкової композиції на
  широкому екрані; жодних горизонтальних скролів.
- Перевірити: login → register link; register → login link; ім'я/email у
  шапці; вузький viewport; keyboard focus; typecheck, unit tests, build і
  browser smoke через запущений Docker-стек.

## Поза межами

Без зміни схеми БД, контрактів API, Better Auth конфігурації, Redis/BullMQ і
життєвого циклу нотаток. Вихід із акаунта не додається, бо його зараз немає в
узгоджених auth-сценаріях.
